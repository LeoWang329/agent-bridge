# graph 真跑一次挖出来的七条 —— 2026-07-31

**怎么来的**:用 agent-bridge-graph 真跑了一个场景,审的是三天前刚推上去的那 729 行新代码
(`de00ecc~1..7aeafa5`,几乎全在 `tools/node-core.mjs`)。那批代码**只有 codex 审过,而且审了三轮**。

编排形状(脚本见提交说明,一次性,没进仓):

```
第 1 波  codex / deepseek-v4-pro / claude 三家并发,各审一块互不重叠的新代码(scope 划死,要 JSON)
   ↓    普通 JS:过滤 + 解析,一次 AI 都没叫
第 2 波  交叉挑刺 —— 每份报告轮转交给**另一家**核实,谁都不核自己那份
   ↓    普通 JS:计票
产出    只有计票和"被确认成立"的那几条进主 agent 的眼睛;六份长报告一个字都没进
```

6 个环节 / 17 分钟 / 退出码 0 / 零残留。

**结论:值。** 一家审三轮没发现的东西,换两个脑子一轮就出来了 —— 而且不是风格意见,是能指到行号、
能当场复现的缺陷。另外两条是拿 Playwright 打开观测台量出来的。

## 一、代码缺陷(5 条,均已复核 + 已修)

### 1. 堆栈行号被判成欠费 — `classifyFailure` 的判据表

判据表里有裸的 `\b402\b` / `\b401\b` / `\b403\b` / `\b429\b`。而 `node-core.mjs:402:11` 这种
堆栈行号,`402` 两侧都是非词字符,`\b` 照样成立。这个文件自己就 3874 行,而分类读的是现场
日志的 **64KB 尾部** —— 撞上堆栈几乎是必然。

同一张表里还有裸的 `billing`(命中 "see your billing page for usage details")、
`capacity`(命中 "disk capacity of the target volume")、`slow down`。

**为什么要紧**:`failureKind` 是编排用来分派的字段。判成 `quota` = 让人去充值页面,
而实际是个普通崩溃。**误判比漏判贵得多** —— 漏判只是"不知道,你自己看现场"。

**修**:数字必须带上下文(`http` / `status` / `code` / `error` 打头,或后面跟标准短语);
日常英文词要么带上下文(`at capacity` / `capacity exceeded`)要么删掉。
判据表**不再收留任何孤零零的日常词**。

### 2. 代码跟自己的注释相反 — 来源优先级被类别顺序压过

`classifyFailure` 的注释白纸黑字写着「证据按"离后端多近"取:先 `error`、再桥自己的 stderr,
都不匹配才去读现场 `session.log` 的尾部」。可循环写的是**类别在外、来源在内** ——
于是类别表的先后压过了来源的先后。

实测:`error` = "authentication failed: invalid api key",日志里飘一个 `billing`,
因为 `quota` 在表里排第一,结果判成**欠费**。

**修**:来源在外、类别在内。最权威的那份证据先被问完所有类别,才轮到下一份。

### 3. 前一轮的话污染后一轮的判定 — `session.log` 没有轮边界

`saveScene` 每轮把**整个会话**的 `session.log` 整份拷进那一轮的现场,分类再读它的 64KB 尾部。
多轮对话里,第 1 轮正常答复中提到的词会被算进第 2 轮的失败判定。

同一个毛病桥 stderr 那边**早就用水位线解决了**(`markStderrWindow` / `stderrWindow`),
这一路当时漏了 —— 一个毛病修了一半。

**修**:本轮开跑时记下会话日志的字节数,分类不许往那之前读。凭据里也如实标 `session.log(本轮)`。

### 4. 判「是不是 Windows」,该判「文件系统区不区分大小写」 — `ownedEntries`

`fold = (s) => (IS_WINDOWS ? s.toLowerCase() : s)`。而 macOS 默认的 APFS **同样大小写不敏感**。
于是在 macOS 上:`existsSync("Foo.receipt.json")` 命中磁盘上的 `foo.receipt.json` 返回真
(走进归档分支),前缀比对却一个都匹配不上 —— 归档列表为空、什么都没搬,
紧接着这一次把 `foo.*` 覆盖掉。**现场无声销毁,而留档正是 `retryFailed` 的全部意义。**

讽刺的是函数上方的注释**早就把机理写对了**(「决定这两个名字是不是同一个文件的是文件系统,
那判归属就得用它那套规则」),判据却写成了平台。

**修**:两处。①大小写规则**探出来**(拿已读到的目录清单翻转一个字母去问文件系统,不写探针文件);
②不管什么成因,**进了归档分支却一个都没认出来就响亮报错、一个字节都不覆盖** ——
闸设在"搬了几个"上,而不是设在"是不是那个已知成因"上。

### 5. 降级闸比的是「状态值变没变」,该比「这个判定是不是过期了」 — `reconcileOutcome`

原判据 `run.kindForStatus !== receipt.status`,也就是拿**值变没变**当**有没有发生新的降级**的
代名词 —— 两回事。一轮已经以 `unknown` 收场并被判成 `rate_limited`,收尾又因为工作区交付不明
把结局压成 `unknown`:**值一模一样**,于是这道闸整个跳过。

结果回执长成 `status:"unknown"` + `failureKind:"rate_limited"`:
意思是"不知道后端干没干",读起来却是"限流而已,重跑就行" ——
而重跑常带 `force`,`force` 会删掉**正因为说不清才被保留下来**的那棵工作树。
这恰恰是 `finalizeRun` 里那段注释花了六行去防的事,却在紧接着的下一个函数里漏了出去。

**修**:改成代号(epoch)。收尾每降级一次代号 +1,分类记下自己是第几代做的。
"这个判定过期没有"是**直接问出来**的,不是拿值推的。

> 同一个形状栽过不止一次(判据换到第四版那次也是):
> **拿某个字段的值去推断"有没有别的事情发生过",只要两件不同的事能算出同一个值,判据就漏。**

## 二、观测台缺陷(2 条,Playwright 量出来的)

### 6. 运行中时钟会冻住

两次实测,页面顶着绿灯**「实时」**:

| | 页面显示 | 墙上时钟 |
|---|---|---|
| 第一次 | 已跑 **8s** | 已跑 **281s** |
| 第二次 | 已跑 **5m08s** | 已跑 **494s** |

两次差值都**精确等于**"距最后一条事件的时间"。根因:`index.html` 拿最后一条事件的时间戳当"现在",
而桥内部按 5 分钟切片 wait —— 模型思考期间一条事件都没有。

**为什么要紧**:观测台就一个用途——判断「还在动还是卡住了」。冻住的那几分钟恰好是最想知道
答案的时候,而且方向是反的:一个安静了五分钟的 run,看起来像**刚起步**。

代码里有人想到过(有个 `stale:true` 的开发样例),但**没有任何代码产生它、也没有任何代码读它**,
是条死设定;而且那是给"断线"设计的,跟这个情况正相反 —— 这儿连接好好的,只是没事件。

**修**:真连着一个活着的 run 时用墙上时钟,并每秒自己走字。顺带两件:
- 静态归档不走字(那里没有"现在"可言,走字就是编数字)。
- **修过头的地方自己堵上了**:独立用 `VIZ_OUT_DIR=…` 打开归档时根本没有 owner 管道,
  `owner-lost` 永远不发,于是一份**跑到一半被中断**的归档会一直显示"运行中"——
  这是既有的谎,以前只是不涨、现在会涨。改成:没有 IPC 父进程就如实发 `owner-lost`。
  (归档完整时那道 `!sawRunFinal` 的闸照常压掉它,正常归档一条控制帧都不多发。)
- 详情面板的滚动位置现在跨重绘保住了 —— 否则每秒走字会把读者的滚动条持续弹回顶部。
  (这个毛病其实**以前就有**,只是以前只在来事件时弹一下。)

### 7. 推断边「点开看依据」实际点不开

图例写着「推断(可点开看依据)」,弹窗内容也做得很好(诚实地说明"这是猜的、按文件名子串匹配、
没校验过因果")。但线宽 1.4px 而且是虚线,`pointer-events:stroke` 让**命中区就是那条线本身**:

- 用 `getPointAtLength` 算出的**曲线数学中点都点不中** —— 正落在虚线的空隙里(5px 实 5px 空)。
- 在离线 ±6px 的 49 个落点里扫,**只有 4 次点中 = 8%**。
- `<path>` 不可聚焦,**键盘完全够不到**。

**修**:底下另铺一条 18px 的透明粗线当热区(看不见、不改观感),带 `tabindex` + `role=button`,
键盘 Tab 能走到、回车看依据、焦点有可见描边。
**实测命中率 8% → 100%**,数学中点也点得中了。

## 二之二、会话观测台缺陷(2 条,写真浏览器 e2e 时当场抓到)

按要求给两个观测台补真浏览器 e2e,页面**一打开**就抓到:

### 8. 每秒抛一次 ReferenceError,定时刷新整个死掉

`index.html` 的 `updateHeader()` 调 `secsSince(...)`,而这个函数**在 `reconcile.mjs` 里没有 export**,
页面的 import 列表里也没有它 —— 于是每次调用都抛。

炸掉的范围比看上去大:它在**1 秒一次的定时器**里被调用,抛出之后同一个回调里紧跟着的
`if(hasRunning) scheduleRender();` **永远执行不到** —— 页面的定时刷新死了,
进行中的轮次耗时、活跃度读数全都不再更新。它还在 rAF 渲染回调的末尾,把 `updateJump()` 一起带走。

**修**:`reconcile.mjs` 导出 `secsSince`,页面与**生成器 `build-index.mjs`** 的 import 列表都补上
(只改产物的话,下次重新生成又会回来)。

### 9. 设计稿的样例读数留在了产品页上

`#runElapsed` 静态写着 `35分33秒`、`#runCount` 写着 `7 个会话 · 2 进行中` —— 设计稿的假数据。
本该被首帧真实数据覆盖,可**上面那条缺陷正好让覆盖不发生**,于是页面一直挂着
「本次运行 35分33秒」:一个纯属虚构、却看起来完全合理的时长,用户无从察觉。

两个缺陷**单独都不致命,凑齐才骗人** —— 而它们就是一起出厂的。

**修**:占位换成中性的 `--`,并在生成器里加一道替换(设计稿的样例数据本来就该和原型控件一起被剥掉),
于是"渲染断了"长得像"渲染断了"。这和本仓到处那条纪律是同一条:
**不知道就如实说不知道,不能编一个看起来对的数。**

> ⚠️ 这一条是**变异验牙逼出来的**,而且逼了两轮:
> 第一版断言只查「本次运行有读数」,把两个缺陷一起还原之后它**照样全绿** —— 假读数顶在那儿。
> 于是断言改成**查值对不对**:夹具知道这次 run 是多久前起的,页面上那个数就得对得上
> (差 10 秒以内)。现在还原出厂状态时它红得干脆:「页面 `35分33秒`(=2133s),按夹具应为 ~239s」。
>
> **教训:「非空」这种断言,任何看起来合理的默认值都能骗过去。** 真有牙的是两类 ——
> 查**行为随时间的变化**(读数会不会自己走字)、查**值对不对**(拿夹具已知的事实去核)。

## 三、一个流程问题(已修)

deepseek 把合法 JSON 裹进 ```` ```json ```` 围栏,**重问那一次照裹不误**
(而重问的提示词里已经明写"不要 markdown 代码围栏")。于是全系统唯一那次 reask 被烧在一个
**其实答对了**的输出上,那个环节报废 —— 连带 codex 的 3 条发现没人核。

**修**:围栏是**包装**,不是格式错。原样解析不了、剥掉能解析 ⇒ 剥掉,判合格。

⚠️ 这里有个反直觉的地方:**只放宽校验、不动文件是更坏的**。产出是**先落盘、后校验**的,
所以光让检查放行会让节点报 `ok`,而磁盘上那份仍然 `JSON.parse` 不了 ——
失败被推迟到调用方那儿,还没了线索。所以 canonical 产出里写的是剥完的正文
(「字节直传」唯一的例外,必在 `diagnostics` 里说明),模型原话完整留在**本次尝试的审计原件**里。
