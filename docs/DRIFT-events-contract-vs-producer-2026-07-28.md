## 0. 这份文件解决什么

真理源的优先级在复审简报里写死了：**`docs/EVENTS-graph.md` 定 wire**。所以下面每一条的**默认方向是「改代码」**，

D6 让页面分不开「确知没有改动」与「探测失败、说不清」。
**只修 codex 点到的那三处会留下另外三处。**

## 2. 为什么七条全部改代码，一条合同都不改

逐条问过「是不是合同写错了」：

- **D1**：合同那三个键是**逻辑名**，文件名是 `session.log`/`answer.txt`/`status.json`。
  用文件名当 JSON 键读着顺，但**键里带点**会让所有 `a.b.c` 形式的取值失效，
  而合同那张「逐槽定死」的判据表（§3.2）通篇用的是逻辑名。**合同是对的。**
- **D2 / D3**：都是「少了一个事实」，没有任何理由。
- **D4**：合同的处置（取不到就不发）比代码的处置（发一条 null）**严格更好**，
  理由在合同里写着，我认同。
- **D5**：恒在＋可 null 比可缺席好，理由同 §3.1 对 `AssetState` 的一贯口径：
  **「不许用缺席表达未知」**。
- **D6**：`filesChanged` 无上限这一条是硬的。`changesKnown` 少了会让页面把
  「git 探测失败」渲染成「没有改动」—— 正是本项目反复栽的那类错。
- **D7**：查过之后**不成立**，闸已经在了。列在这里是为了留下「验过」这个事实。

## 5. 第二轮：把 D1–D6 改完之后又浮出来的三条

前四节是**复审提出来**的那一批。下面三条是**改完之后**才照出来的 ——
它们能被照出来，是因为这一轮多做了两件事：样例改成按合同独立构造（不再照抄生产者），
以及把合同里那些**跨字段的等式**抽成一份独立实现（`viz/contract-invariants.mjs`），
让**写方**与**冻结样例**各过一遍。

| # | 事实 | 合同怎么说 | 生产者怎么做 | 定向 |
|---|---|---|---|---|
| D8 | `workspaceSummary` 的六个键拿不到时 | 「可 null」，字段封闭 | **整个键不出现**（`if (w[k]) ws[k] = …`） | **改生产者**：六个键恒发，拿不到发 `null` |
| D9 | 一轮的产出（`node:turn-settled.output`） | `sha256` 等于该轮最后一次成功复制的那项 attempt 的 output；归档布局里**只有** `attempt-<n>.output.md` | 又拷了一份 `turns/<key>/attempt-last.output.md` | **改生产者**：直接沿用那一项的资产 |
| D10 | `SceneState.files` 的键 | 逻辑名 `sessionLog`/`answer`/`status` | 生产者对，**消费者（reducer）错**：按磁盘文件名读 | **改消费者** |

### 为什么这三条第一轮没被抓到

- **D8** 两边都能被页面读成「没有分支」，所以**从来不会炸**。它的代价是隐性的：
  一个照合同实现的消费方会去分「明确没有（null）」与「不知道（缺席）」两档，
  而写方**从不产生前一档** —— 那段分支从写下去的第一天起就是死代码。
- **D9** 两份字节**内容相同**，所以任何「比 sha256」的检查都过。抓住它的是
  「比 `ref`」—— 而会去比 ref 的，只有一份照着 §1.3 那张归档布局表写出来的检查。
  合同对这类副本的判词已经写在那里：**两份「本该相同」的字节迟早会被改成不同**。
- **D10** 是**同源绿灯**的教科书例子：reducer 按文件名读，样例也按文件名造，
  于是所有现场断言全绿 —— 测的是「我和我自己一致」。样例一改成按合同造，当场变红。

### 这一轮留下的守卫

`viz/contract-invariants.mjs` **刻意不 import `viz-events.mjs`**：schema 只管单个字段的形状，
管不了「这两处 sha256 必须相等」「这个字段只在那个字段不是 present 时才许出现」。
两个调用点都在推送前必过的回归里：

- `viz/test-viz.mjs` —— 验**冻结样例**（消费侧的地基：样例歪了，后面每条断言都在验假合同）
- `docs/repro-mcp-hang/repro-graph-viz.mjs` —— 验**每一次真跑出来的 transcript**（写方有没有漂）

D9 就是接上第二个调用点之后**当场**红的。

### D8 的方向被复审推翻过一次（记在这里，因为推翻的理由比结论更值钱）

我第一次的处置是**改合同跟随生产者**：既然写方从不发 `null`、拿不到就省略键，
那就把文档改成「可缺席」。看起来是"让文档说实话"。

第二轮复审指出这是**放宽过头**：`workspaceSummary` 整块只在**回执没归档成功**时才出现，
它存在的全部意义就是「回执没了，人还能靠它找到现场」。六个键都做成可缺席之后，
一份 `workspaceSummary: {}` 会同时通过 schema 与不变式——**兜底没兜住，却又不报错**，
而页面这时候连"该去核对哪个目录、基于哪个提交"都说不出来。

所以正确方向是**改生产者**：六个键恒发，拿不到的发 `null`。这也回到了本仓对
`AssetState` 一贯的口径——**不许用缺席表达未知**。

顺带定死两件事：`baseCommit`/`headCommit` 是 `git rev-parse` 给的**完整 40 位 SHA**
（短 SHA 会随仓库长大而歧义），schema 与不变式都按 `hex40` 校验；样例里那些
七位的假 commit 也一并换成了真形状。

**教训**：「文档和代码不一致」有两个方向，选哪个不看谁先写的，看**这个字段是干什么用的**。
兜底层的字段，宁可要求写方多说一句 `null`，也不能允许它一声不吭。

## §6 第 3 轮补救之后又自己揪出来的三条（2026-07-29）

前五条是复审点出来的；这三条是**在给前五条补门禁的过程中掉出来的** —— 顺序本身值得记：
先有"这条修复没有任何测试守着"这个念头，才有后面两个真 bug。

### D11 —— 用来判对错的检查器自己会崩

`viz/contract-invariants.mjs` 不变式②：

```js
if (a.inputSha256 !== t.inputSha256 || a.input.ref !== t.input.ref) …
else if (!a.input.ref.endsWith(`/turns/${a.turnKey}/prompt.md`)) …   // ← 这里
```

归档失败时 `input` 是 `unavailable`、**压根没有 `ref`**。两边都 `undefined` ⇒ 上一行判"相等"，
于是走进 `else if`，`undefined.endsWith` 当场抛。

坏处不是"少查一条"，是**整份 transcript 一条都没查成**：调用方看到的是「炸了」，
而不是「哪条不变式不成立」。**一个只在数据完美时才敢跑的检查器，等于没有检查器** ——
而它存在的理由恰恰是"数据不完美的时候告诉我"。

修法不是加个 `?.` 把它绕过去（那是把崩溃换成静默漏检）。正确的口径是想清楚
**这两个字段指的是不是同一份东西**：attempt 1 的输入**就是**该轮的 `prompt.md`，同一个文件。
所以它们的归档结局必须**同生同灭** —— 一边 `present` 一边 `unavailable`，
是同一份字节有了两种命运，那是记录本身在自相矛盾，该判红。指纹（`inputSha256`）
与归档是两件事，指纹无条件比。

### D12 —— 同一条规则只落实到一个字段

`viz-node.mjs: rewriteReceipt` 把 ref 重写进归档目录之后，删掉了 `diffPath`，
理由就写在紧挨着的注释里：canonical 区那份会被同 id 带 `force` 的下一波**原地覆盖**，
留着路径 = 给读的人一条"打开这个"的指示，而打开之后读到的是**另一次运行**的字节 ——
**伪造历史，比缺失更糟**。

但 `artifactPath` 三层（顶层 / 轮 / 每次尝试）原样留着。同一段代码、同一条理由、
隔着几行，一个删了一个没删。

这与 §1.3 里那句"新增一层就要重写一层"是**同一个坑的两种长相**：
前者是"同一个字段漏了某一层"，后者是"同一条规则漏了某个字段"。
所以新的不变式⑬**刻意不列字段清单** —— 列清单就是等着漏下一个 —— 而是按
「有 `xxxRef` 就不许有 `xxxPath`」整棵树反推，新增一层 ref 时它自动跟着覆盖。

⚠️ 判据**不是**"长得像绝对路径就违规"。第一版就是这么写的，当场把 `workspace.path` 判红了 ——
而那个绝对路径是 §5.8 **点名要的**：回执没归档成功时，它是人**找回现场**的唯一线索。
"绝对路径"不是罪名，"给出一条指向会被覆盖的证据的指针"才是。

### D13 —— 两处修复此前一条断言都没有

第 3 轮的 #37（复用逐 attempt 归档）与 #40（`workspaceSummary` 六键）都属于
**改完就绿、但绿是因为没人考**：

- 复用只有 V6 一个场景，那个节点**只有一次尝试** —— "逐次归档"与"只归档最后一份"
  在它身上**长得一模一样**，考不出任何东西。
- write 节点在 viz 这一侧**一个场景都没有**（worktree 那套回归不开 viz），
  于是顶层 `diffRef` 与 `workspaceSummary` 只被我自己手搓的冻结样例考过 —— 同源自证。

补上 V6b（真跑 `#1 rejected → #2 accepted` 再复用）与 V12（write + 归档子目录被占住）
之后，D11 与 D12 都是**当场**掉出来的。

顺带记一个夹具教训：V12 第一版塞了个只读节点当对照，结果 `FAKE_OMP_MODE` 是**进程级**的，
`writeturn` 让那个"只读"节点往主工作区写了个文件，把后面 write 节点的干净基线闸踩爆。
**夹具的模式是进程级、节点的能力档是节点级**，两者不在一个粒度上 —— 想在同一个 graph 里
混不同后端行为，得换别的办法（这里的处置是把 read 节点那两条断言搬去 V1）。

## §7 第 4 轮复审：两条阻塞 + 三条高（2026-07-29）

这一轮最值得记的不是某一条,而是**它们的共同形状**:全都是「**一个名字被读成了它不是的意思**」。

### D14 —— `changesKnown` 被读成「确知没有改动」(阻塞)

页面:`netEmpty = outcome === 'delivered' && changesKnown === true`,并据此写
「已交付,但这次提交没有净改动」。

而生产者只要 git 探测**正常返回**就置 `changesKnown = true`(`node-core` 里那一行紧跟在
探测成功之后、**在判断有没有改动之前**)。改了十个文件、正常交付的节点同样是 `true`。

于是页面会对着一次真实的交付,斩钉截铁地说"没有净改动"。**一句凭空捏造的结论,
而且它长得比真话还确定** —— 用户没有任何线索去怀疑它。

更糟的是 `test-viz` 里那条断言写着「changesKnown:true 说的是『确认过没有改动』」,
把这句假话**冻成了正确预期**:一次确定的假绿。

- 正确判据:「净改动为零」= **diff 自己是零字节**(真实形状是一个**空提交**:HEAD 动了、
  净改动为零,所以它既不是 `no-changes`——那要求 HEAD 也没动——也不该当普通交付渲染)。
- `changesKnown` 只该回答「**探到了没有**」,一个字都不许提"有/没有改动"。

**教训**:字段名里的 `known` 是**认识论**的,不是**事实**的。
`xKnown` 永远只表示"x 这件事我们测出来了没有",绝不表示 x 的取值。

### D15 —— 复用重新归档「审计原件」,而复用闸从没验过它们(阻塞)

§6 的 D13 补上了"复用逐次归档"的门禁,但只考了**挂对了没有**,没考**有没有被改过**。

复用闸(`checkReuse` / `replayTurn`)当时只核对**轮级最终产出**的路径与 sha。
而 `emitReusedSettled` 会把**每一次尝试**的 `artifactPath` 重新归档、
**按当前磁盘字节现算一个 sha** 发到 wire 上,页面据此说"这就是当初第 n 次写下的东西"。

于是:首跑之后手改一下 `<id>.a1.md`(或者把回执里那条路径指向别的文件),复用照样成功,
第二个 graph 把**篡改过的字节**包装成一份崭新的 `present` —— 指纹与篡改后的内容自洽,
**页面上一点红都不会有**。而"被打回的那一次到底写了什么"正是复审时最想看的东西。

⚠️ `emitReusedSettled` 的注释当时白纸黑字写着「归档时机在复用闸之后,那道闸刚刚**逐项**
坐实了每一轮的产出 sha」—— **注释描述的是一个不存在的保证**。

修法是 `assertAttemptsIntact`:有 `artifactPath` 就必须路径是本次算出来的、文件在、
指纹是合法 hex64 且逐字节对上;**没有** `artifactPath` 才放行(当初没留原件是**选择**不是故障)。

**教训**:**扩大了"被使用的范围",就必须同步扩大"被验证的范围"。**
D13 补的是"这份修复有没有被测到",这一条补的是"这份修复用到的东西有没有被验过" ——
两个问题不一样,而第二个更容易漏,因为**代码注释会替你回答它**。

### D16 —— `sceneRef` 与同一份 JSON 里其它 ref 用了两种基准(高)

`artifactRef`/`diffRef`/`inputRef` 全是 out-dir 基准(`nodes/.runs/<graphId>/<seq>-<id>/…`),
只有 `sceneRef` 发的是裸的 `turns/<key>/scene`。同名后缀、两种基准。
消费方按同一套解析必然解错;serve.mjs 那道闸更是明确要求 `nodes/.runs/<graphId>/` 开头 ——
拿裸路径去取现场只会拿到 403,而页面会把 403 显示成「文件丢了」。

顺带暴露了 §6 里新加的不变式⑬**太弱**:它只查"有 `xxxRef` 就不许有 `xxxPath`",
证明得了"canonical 路径删掉了",证明不了"**换上去的这一条是对的**"。
现在⑬还要求每个 `xxxRef` 本身是**本 graph 内的合法 ref**。

⚠️ 写这条时差点栽在 `refLooksLegal` 的返回约定上:**它返回的是原因字符串,合法时才是 null**。
写成 `!refLooksLegal(…)` 会把判据整个反过来 —— 合法的全报错、非法的全放行,
而且**照样"有断言"**。

### D17 —— `fingerprint-only` 在生产者与校验器眼里是两件事(高)

生产者 `markOutputFingerprintOnly` 明说**不打 `hadLocal`**(这一项没有本地副本,
不该参与"最后一次成功复制"的选取);而 §6 里我给不变式③写的 `hadLocal` 是
「只要不是 `source-missing` 就算有过」—— 正好相反。

后果不是"少查一条":最后一次尝试只剩指纹时,生产者选**更早那次**当最终产出、
校验器选**最后那次**,**同一个问题两个答案**,而这条不变式的全部意义就是判它们一致。

正确的分类不是二分,是按 code 分两类:
- **没有本地原件**:`source-missing`(从来没有过)、`fingerprint-only`(有过,这一次够不着)
- **有本地原件、只是这一层没保住**:`write-failed` / `sha-failed` / `archive-root-failed`

### D18 —— 合同承诺了"输入找得回来",代码从没做过(高)

§5.9 明写:复用命中时,每一轮 attempt 1 的输入**仍能从本次冻结的那一轮正文恢复**
(`turnSpecHash` 已逐项比对 ⇒ 正文必然是同一份字节),n≥2 才只剩指纹。

而 `emitReusedSettled` 里只有一句"没有 `inputRef` 就标 `fingerprint-only`",
于是**每一次输入都成了「只剩指纹」** —— 连 attempt 1 那份**这一次刚冻结好、就躺在归档里**
的正文也不例外。页面对着一份现成的原文说"拿不到"。

修法照 §5.9 的原话:归档器可以构造候选,但**只有候选的 SHA 与 `inputSha256` 逐字节一致
才落盘并给 `present`**,对不上退回 `fingerprint-only`。**既不造内容,也不给死链接。**

### 这一轮的元教训

四轮下来,复审的产量是 **8 → 5(2 阻塞)→ 2 阻塞+3 高**,并没有单调收敛。
原因很清楚:**每一轮修完都会长出新的表面积**。这一轮的两条阻塞里,
D15 直接源于上一轮 #37 那个修复(扩大了归档范围),D17 直接源于上一轮我新写的不变式③。

所以"上一轮全绿"从来不等于"这一轮没问题",它只等于**上一轮问到的问题都答对了**。

## §8 第 5 轮复审：2 阻塞 / 1 高 / 3 中 / 3 低(2026-07-29)

**先更正 §7 里两条我自己总结错方向的话** —— 这比新发现更值得记,因为它们是**上一轮
刚写下的"教训"本身就是错的**:

### 更正 A:§7 D15 把「没有 artifactPath」总结成了"合法选择"

原话是「**没有** `artifactPath` 才放行(当初没留原件是**选择**不是故障)」。**方向错了。**

v2 的逐次审计原件**与 viz 开关无关**(`attemptArtifactPathFor` 的注释白纸黑字:
「**每次尝试恒写一份产出原件**,与 viz 开关无关」),而 v1 的回执在版本闸上**已经被拒**。
所以"当初没开 viz 所以没有原件"这个理由**在 v2 里根本不成立** —— 真正会留下无路径项的
只有**当时那次复制失败**。

而「复制当时失败」与「事后把证据字段删掉」在回执里**长得一模一样**,现有结构没有字段能区分。
所以正确的说法不是"这是合法的",而是:

> **拒不了,但后果是有界的** —— 那一项被投影成 `fingerprint-only`,页面拿不到任何字节。
> **删字段能让证据消失,不能让证据变假。**

这两句话的差别很大:前者让人以为这条路已经关上,后者才让下一个人知道**这里还开着一道缝**。
测试也跟着改了:V6c 那一格原来断言"放行=对的",现在断言的是**那个有界后果**。

### 更正 B:§7 D16 把「本 graph 内合法」当成了终点

⑬当时只验 ref 在 `nodes/.runs/<graphId>/` 底下。但**同一个 graph 里别的节点的目录
同样满足这个前缀** —— 一条指向**另一个节点**的 ref 照样全绿,页面会拿到一个 200,
内容是别人的。§1.3 要的是**闭包到当前 `<nodeSeq>-<id>/`**。

现在⑬按"这份 receipt.json 自己所在的那个目录"做前缀(从它自己的 ref 推,不另拼一遍),
并且**要求目标真的存在**(⑧ 只遍历事件里的 AssetState,不会打开 receipt.json 去看里面这些裸 ref)。

### D19 —— `attempts[]` 的**顺序**是承重的,而没有任何地方验过它

`emitReusedSettled` 按**数组顺序**归档、把**最后一个**当成该轮产出与顶层交付物;
不变式③也按同一个数组顺序取"最后一项"。

于是把 `[#1 rejected, #2 accepted]` **对调一下**:两个文件都在、两个 sha 都对得上、
每一项自身都合法 —— 而页面会把**被打回的那一份**当成最终交付物挂出来,
**生产者与校验器一起假绿**(它们读的是同一个被篡改的顺序)。

⚠️ 同一处还藏着一个路径逃逸:`attempt.n` 从没被校验过,而它**同时**参与
"本次算出来的可信路径"(`attemptArtifactPathFor` → `path.join`)与归档目标路径。
把 `n` 塞成 `"../../x"`,闸门用同一个 `n` 算出同一个逃逸路径,**自己和自己比当然相等**。

修法是一条规则同时堵住两者:`n` 必须是 **1..k 严格递增**。再加一条
"收在 ok 的轮,最后一次必然是 accepted / no-output"(§5.6 的判定表直接推得出)。

**教训**:**一个字段是不是承重,看的是"谁按它做决定",不是它长得像不像数据。**
`n` 看着只是个序号,实际上是一个**路径构造参数**;数组顺序看着只是排版,实际上
决定了"哪一份是交付物"。

### D20 —— "先写下来再看对不对"

`recoverAttemptInput` 先 `putText` 落盘、再比对 sha。而 §5.9 的原话是
「只有候选的 SHA 与 `inputSha256` 逐字节一致**才落盘并给出 present**」。

先写后验时,对不上的那次事件确实降级成了 `fingerprint-only` —— 可归档区里**已经躺着
一份没能自证的候选正文**,一份谁也说不清来历的文件,恰恰是这套归档最不该有的东西。

⚠️ 而 V6b 只断言"最终 sha 相等",**先写后验的错误实现照样全绿**。

### D21 —— 一条"只有路径错"的用例,其实同时也 sha 错

V6c 那一格把 `artifactPath` 指向 `a2`,但 `a2` 的内容与 `a1` 不同、sha 也不同。
于是**先被 sha 那道闸拒掉了**,路径闸有没有区分度**根本没被考到** ——
把生产代码里的路径等值检查整个删掉,测试照样全绿。

改法:让替身与记录的 sha **自洽**(复制一份 `a1` 出来,只改路径),这样只有路径闸能拒它。

**教训**:**一个用例同时踩两道闸时,它证明的是"至少有一道闸在",不是"这道闸在"。**
要考某道闸,得让别的闸**全都通过**。

### 这一轮的元教训

五轮的产量:**8 → 5 → 5 → 7 → 9**。不但没收敛,还在涨。

但涨的原因不是代码在变坏,是**每一轮的修复都把可攻击面推进了一层**:
第 3 轮补了"复用要逐次归档",第 4 轮才问出"那些被归档的东西验过没有",
第 5 轮才问出"验的时候用的那个 `n` 本身可信吗"。这是**同一条链上越来越深的三个问题**。

所以"复审收敛"本身可能就是个错误的期待。更靠谱的判据是:
**新发现是否还在同一条链上越挖越深(健康),还是开始重复上一轮已经答过的问题(才是收敛)。**

## §9 第 6 轮复审:我上一轮那句"证据不会变假"是错的(2026-07-29)

### 更正 C:§8 说「删字段能让证据消失,不能让证据变假」—— **反了**

上一轮我写下这句话时,只验证了一种删法:**把所有尝试的 `artifactPath` 全删掉**。
那种情况下归档器会退回整轮产出(它被闸验过),所以确实不会变假。

但只要**只删末次(accepted)那一项**、留着前一次 rejected 的:

- 闸门放行(缺路径是允许的 —— 复制当时可能真的失败);
- 归档器早先的回退条件是「**一次都没归档到**才退回整轮产出」,而 rejected 那次归档到了,
  于是回退**整个不跑**;
- "该轮产出 = 最后一份成功复制的 attempt 产出"于是选中了**被打回的那一稿**;
- 它一路升成轮产出与顶层交付物,不变式③按同一口径选中同一项 —— **两边一起假绿**。

**一个字段被删掉,一份被否决的草稿就成了正式交付物。** 这正是"证据变假"。

修法是把回退的判据从「有没有任何一次归档到」换成「**最后那一次**有没有自己的原件」——
因为该轮的最终产出**恒等于最后那一次的产出**(闸已坐实:收在 ok 的轮,末次必是 accepted/no-output)。

⚠️ 我给这条修复补的第一版测试**恰好绕开了这个形状**(它删的是全部,不是只删末次)。
所以真正的教训不是"再补一个用例",而是:

> **一个"删字段"的用例,删的是哪一个字段,决定了它考的是完全不同的东西。**
> 「全删」与「删一个」在这里是两条独立的路径,而**前者恰好是安全的那条**。

我把旧行为临时改回去跑了一遍作负对照:被打回那一稿("REASK_BAD_1 这次没按格式说")
确实同时成了轮产出与顶层交付物,4 条断言一起变红。

### D22 —— 闸只验了"文件",没验"故事"

`assertAttemptsIntact` 当时只核对路径与内容指纹,而回执里**同时被原样重新发布**的还有:
`status`、`inputSha256`、`charCount`/`byteCount`。于是:

- 把第 1 次从 `rejected` 改成 `accepted` ⇒ 一份**形状合法、内容却是假的**审计记录
  (页面上两次都显示"被采纳",而当初真实发生的是"第一稿被打回");
- 塞进第 3 次尝试、或塞一个枚举外的 `status` ⇒ 一路走到**事件 schema** 才被拒,
  而那里被 `guard()` 吞掉:**业务照常返回"复用成功",页面却永远等不到 `node:settled`**。

后半句才是最坏的:观测层"永远无权改变业务结局"这条纪律是对的,但它意味着
**凡是能走到事件层才失败的东西,都会变成一次静默的观测缺失**。所以校验必须前移到闸上。

补的几条都是**能从合同直接推出来的**,不是拍脑袋:
`reask ∈ {0,1}` ⇒ 次数上界 `reask+1`;走到下一次的唯一出口是"这一次被判不合格"
⇒ 非末次只可能是 `rejected`;`no-output` 的字面意思就是零字节 ⇒ 它与非零 `byteCount` 自相矛盾。

⚠️ **顺序也是承重的**:逐字段的形状必须先查、字段之间的关系后查。反了的话,
一个枚举外的 `status` 会先被"非末次只能是 rejected"拦下,于是**枚举那道闸有没有效永远没人知道**
——测试里它天然撞不到。这不是风格问题,是"这道闸可不可观测"的问题。

### D23 —— 拿被检查的值去算它自己的合格标准

⑬ 当时这样算本节点的归档前缀:

```js
const nodePrefix = r.ref.replace(/\/[^/]*$/, "/");   // 从 receipt 自己的 ref 推
```

**这等于没检查。** 把节点 A 的 `receipt` 整个换成节点 B 那份**真回执**:B 的内部引用彼此自洽、
目标文件也都在,⑧ 与 ⑬ 一起全绿 —— 而页面会在 A 名下端出 B 的回执。
**跨节点的证据错配,而且看起来毫无异常。**

正确的算法是从**这条事件自己声明的身份**推:`nodes/.runs/<gid>/<nodeSeq>-<id>/`
(`nodeSeq` 来自这条 `node:settled`,`id` 来自该节点的 `node:observed`),
再要求 `receipt.ref` 恰好等于那个目录下的 `receipt.json`。我用冻结样例做了内存交换验证:
改之前 PASS(漏),改之后 FAIL 并指出"应为 …/0-survey/receipt.json,拿到 …/1-audit-auth/…"。

**教训**:**判据的来源必须独立于被判的那个值。** 这一条听起来是废话,但它在代码里的长相
非常无害 —— "从 ref 推目录"读起来甚至像是在避免重复。

### D24 —— 合法的零字节成功,被复用闸当成"文件坏了"

§5.6 有 `no-output` 一档:「**已经确认**产出是零字节」,那是一次**合法的成功**(status 仍是 ok)。
而两条复用闸都写着 `st.size === 0 ⇒ 拒`。后果:同一个任务第二次**永远复用不了**,
只能 `force` 覆盖 —— 而 `force` 会销毁上一次的产出。

空文件的 sha256 是良定义的,内容指纹那道闸照常管得住"被换成另一份文件"。
`SKILL.md` 里"产出文件存在且非空"那句同步改了。

### D25 —— 复用时画的是**上一版推断算法**的边

§5.9 明写「`inferredDeps` **本次重算**」,而 `normalizeTurn` / `normalizeSpec` 确实用同一个算法
重扫了这一次的正文 —— 但复用收尾时用的是**旧回执里存的那份**。
推断算法一改,复用命中的节点就会继续画早已不成立的虚线边;而虚线本来就是"系统按文件名猜的",
再叠一层"猜的是上一版算法的结论",页面上没有任何线索能看出来。

### 这一轮的元教训

六轮产量:**8 → 5 → 5 → 7 → 9 → 9**。

三条更正(§8 的 A、B,以及这一节的 C)全都发生在**我自己刚写下的"教训"**上。
这说明一件事:**复盘写下的结论,和代码一样需要被复审**——而且它更危险,
因为它读起来像是已经想清楚了的东西,下一个人(包括下一轮的我)会直接拿来当前提用。

## §10 第 7 轮(收口轮):**产品全绿,红的是尺子**(2026-07-29)

这一轮把复审范围定死成三类(九处改动的回归 / 页面在**产品自己走得到**的路径上说假话 /
新加的那批测试假绿),明确把"手工改回执才能触发的新攻击面"划到范围外。
结果:**产品零阻塞**,唯一一条结论落在**测试的区分度**上——三处,合成一条。

### D26 —— 一格用例,只考出它**恰好**踩到的那道闸

三处的形状完全一样:**用例过了,但换一个更弱/更错的实现,它照样过。**

| 用例 | 它真正证明的 | 它**没有**证明的 | 补的那一格 |
|---|---|---|---|
| ⑭ 删掉 `inputSha256` | "缺了会拒" | 查的是 **hex64 形状** | ⑰ 换成 `deadbeef`(**非空**但非法) |
| ⑮ 塞进第 3 次尝试 | "超了会拒" | 上界**跟着 `reask` 走** | ⑱ `reask:0` + 塞第 2 次 |
| ⑪~⑯ 全部 | `checkReuse` 那个调用点 | `replayTurn` 那个调用点 | ⑲ 对话回放路径同款篡改 |

三条负对照逐一坐实(每次只改生产代码一处,跑完即还原):

```
把 hex64 换成 `if (!a.inputSha256)`      → 481/1,红的只有 ⑰    (⑭ 照常绿)
把 `reask + 1` 写死成 `2`                → 481/1,红的只有 ⑱    (⑮ 照常绿)
把 replayTurn 里那次调用注释掉           → 480/2,红的只有 ⑲ 两条(其余十六格全绿)
```

第二条的失败信息尤其说明问题:写死成 2 之后那一格**仍然被拒了**,
但拒它的是**下一道闸**("非末次只可能是 rejected")、理由完全无关——
**"被拒了"和"被那道闸拒了"是两件事**,而只断言"拒没拒"的用例分不开它们。

### 这一轮的教训

> **一道闸要考出来,得让它成为唯一可能变红的原因。**
> 做法有两种,缺一不可:**同一道闸至少两种坏法**(缺失 / 畸形——只考"缺失"会把
> 形状检查悄悄退化成非空检查),以及**一道闸有几个调用点就得从几条路进去**
> ——十六格用例全从 `runNode` 进,证不出 `replayTurn` 那条路上闸还在。

⚠️ 顺带说明**为什么这不算"又一次防手改回执"**:这几格考的不是"对手能不能骗过闸",
而是**闸自己有没有被考到**。范围外的是"再挖一层新攻击面",不是"已有的闸其实没被验证"。
