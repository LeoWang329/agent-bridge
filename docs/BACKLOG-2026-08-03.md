**状态：已评估完，等排期。可行性全文在 `FEASIBILITY-session-viz-two-way-chat-2026-08-02.md`，
那份是给业务看的大白话版，这里只留一句结论和开工顺序。**

**要做的事**：session viz 页面上，对**已经闲下来**的委托会话继续提问（不是插话、不是打断）；
它的回答主 agent 照样拿得到；本地归档里要标出这一问一答**是主 agent 提的还是用户提的**。

**为什么不难**：逐轮的问与答本来就分开存（`turns/<会话>/t<N>.in.md` / `.out.md`），
每一轮上已经有一个「谁发的」字段（`source`，现在两个取值），加第三个取值就行。追问本身
底层完全支持——主 agent 平时就是这么追问的。

**开工顺序不能变**：

1. **先给那个网页装锁**（一次性凭证 + 校验请求来源 + 限制请求类型）。
   页面今天只读，所以没锁也还行；**一旦它能发指令，任何一个你打开的网页都能悄悄给你的 AI 下指令**。
   补锁必须在「能发指令」上线之前，不是之后。
2. 页面能对空闲会话发消息 + 加第三个「谁发的」取值 + 那道闸
3. 规范文档 + 检查程序（按规矩，检查程序得是独立写的第二份实现）

**已拍板**：会话有**没取走的结果**时，页面上的发送**直接禁掉**，不是弹个提示让人点过去。
理由：放开不是必然出错，是偶尔出错，而出错时主 agent 拿到的替代品看起来完全正常，没有征兆。

**顺手要修的一个既有小毛病**：`source` 字段的「开场白」那一档，实际运行里**从来没真正出现过**
（开会话时漏了传参数），所有轮次都被标成「后续消息」。现有检查只查「值合不合法」，
查不出「有一档从来没出现过」。**新加一档如果不配一条真跑的用例，会原样复制这个毛病。**

**工期**：约一周（装锁 2~3 天不可省 · 发送+标记+闸门 3~4 天 · 文档与检查程序 1~2 天）。

## 二·补、观测台:图是「长出来的」，不是「摆出来的」

**真实反馈（2026-08-03，用户看第一次演示运行时当场提的）**：
「这个节点不是先预先显示出来的？是跑到哪显示到哪？没有展现出一个图的结构」——**属实**。

**机理**：节点要等脚本真的调用 `runNode()` 那一刻才发 `node:observed`，页面才画得出来；
声明的那条实线是**下游**节点出生时带出来的，所以边总比上游晚出现。跑之前看不到全貌。

**这是设计的直接后果，不是漏做**：skill 明确不做流程引擎（无图格式、无依赖解析、无调度器），
流程活在调用方那段 JS 里，里面有 `if` 有 `for` ——**图长什么样在跑之前确实不确定**
（典型例子：裁判选了谁，才决定下一步找谁修订）。没有声明阶段，就没有东西可以预先画。

**便宜的补法（未动手）**：给脚本一个**可选**的「我打算跑这些、大概这么连」的声明，
页面据此画灰色占位，跑到哪个就实心哪个，**跑完还没实心的标成「没执行」**。

- 诚实性靠标签保住：画的是**打算**，不是事实——跟推断边画虚线是同一个道理。
- ⚠️ **别让它变成调度依据**。一旦有代码去读这份"打算"来排先后，就是在偷偷造流程引擎，
  而 `if`/`for` 写出来的真实流程随时可以跟它不一致 —— 那时页面上会有一张**跟实际不符**的图，
  比现在"没有图"更糟。
- ⚠️ 声明与实际不符时**必须显式说出来**（多跑了没声明的 / 声明了没跑的），不许静默对齐。

## 三、零散的小账

- **命令行入口（`node-turn.mjs`）没有 `--deps`**，所以「上游变了下游别复用」那道闸对它**完全不生效**
  ——从 shell 脚本驱动分波的人拿不到这层保护，而且看不出自己没拿到。
  要么补一个 `--deps a,b`（那道闸是按 `declaredDeps` 走的，通了就自动生效），
  要么在 `tools/README.md` 里明说「命令行这条路没有这道闸，要它就写 JS」。**别默默留着。**

- **`inferDeps` 的正则允许点号**（`nodes/<id>.md` 里的 `<id>` 用 `[A-Za-z0-9._-]+`），
  可环节 id 里不许有点号。于是它能扫出 `foo.t-draft` 这种**永远不可能是环节 id** 的东西。
  今天无害（页面那道「id 在本图恰好出现 1 次」的闸会把它丢掉），但也意味着
  **提问里引用某一轮对话的产出时，推断不出边**。要修的话得先想清楚对话逐轮产物该不该有自己的边。
