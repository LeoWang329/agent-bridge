# 委托会话观测台 —— 怎么用

一个**只读的本地网页**，把这次运行里「开了哪些委托会话、每个会话跑了哪几轮、
每轮问了什么答了什么、有没有被取走」画出来。排查「委托卡在哪了 / 那一轮到底说了什么」用。

> 这份文档是**给使用者的操作说明**，自成一份、不依赖别的文件。
> （数据格式那一侧的实现合同在同目录的 `STATE.md`，写 writer / viewer / 校验器的人才需要看；
> 那份删掉也不影响本文。）

---

## ⚠️ 先看这条：它必须**提前**开

**默认是关的，而且开关只在 MCP server 启动那一刻读一次。** 两个后果：

1. **改了开关要重启客户端**，当场改环境变量对已经跑着的 server 没用。
2. **出问题那次运行当时没开，就没有记录**——记录只在那次运行存活期间存在，事后补不了。

所以：**准备做重度委托、多 agent 编排之前先打开**，别等出事了才想起来。
代价只是本机多一份临时文件（见下面「代价」一节），不影响桥怎么跑。

---

## 一、怎么开

**一句话：让 `AGENT_BRIDGE_VIZ=on` 出现在 `agent-bridge mcp` 这个 server 进程的环境里，然后重启客户端。**

值取 `on`，`1` / `true` 也认，大小写随意。桥不挑客户端，所以「怎么把变量塞进那个进程」
取决于你用的是哪个 MCP 客户端。三条路，任选一条：

1. **在客户端的 server 配置里加 `env`**（最常见，大多数客户端都支持）。
   配置文件里那个 server 条目通常长这样，加一个 `env` 字段就行：

   ```json
   {
     "command": "node",
     "args": ["<装的地方>/scripts/agent-bridge.mjs", "mcp"],
     "env": { "AGENT_BRIDGE_VIZ": "on" }
   }
   ```

2. **客户端 CLI 提供了传环境变量的参数就用它。**
   例：Claude Code 是 `-e KEY=value` ——
   `claude mcp add agent-bridge --scope user -e AGENT_BRIDGE_VIZ=on -- node "<装的地方>/scripts/agent-bridge.mjs" mcp`
   （已经注册过就先 `claude mcp remove agent-bridge`）。别的客户端参数名不一样，查它自己的文档。

3. **设成系统 / 用户级环境变量，再启动客户端。** server 进程从客户端继承环境，所以这条对所有客户端都管用，
   代价是对这台机器上所有客户端一起生效。

**改完必须重启客户端**——开关只在 server 启动那一刻读一次。

**确认生效**：按下面第二步去 tmpdir 找目录，找得到就是开了。找不到就是没生效——
最常见的原因是环境变量没真正传给 server 进程（改完没重启客户端，或者加错了地方）。

## 二、怎么打开页面

⚠️ **桥不会告诉你目录在哪**——它不打日志行、`doctor` 不报、也没有 MCP 工具能查到。
得自己去临时目录里找。这是目前的实情，不是你哪一步做漏了。

**第 1 步：找目录。** 每个活着的 MCP server 进程对应一个：

```sh
# Windows（PowerShell）
Get-ChildItem $env:TEMP -Directory -Filter 'agent-bridge-viz-*' | Sort-Object LastWriteTime -Descending

# macOS / Linux
ls -dt "${TMPDIR:-/tmp}"/agent-bridge-viz-*
```

开了多个客户端就会有多个，按修改时间挑最新的那个；拿不准就看目录里 `meta.json` 的 `pid`。

**第 2 步：起 viewer**（只读，不往那个目录写一个字节）：

```sh
node <装的地方>/skills/agent-bridge/viz/serve.mjs "<上一步那个目录>"
```

省略端口就随机挑一个空闲的。起来之后 stdout 打印一行：

```
session-viz  http://127.0.0.1:53211/   run=mcp-a7c319
```

想固定端口就在目录后面再跟一个数字：`node serve.mjs "<目录>" 8080`。

**第 3 步：浏览器打开那个地址。** 页面自己会实时刷新，不用手动重载。

## 三、页面上能看到什么

左栏是会话列表（可搜索、可按「进行中 / 有问题」筛），右栏是选中会话的逐轮明细：
每轮问了什么、答了什么、什么时候派出去的、跑了多久、结局是什么、正文有没有被取走。
顶部是这次运行跑了多久、开了几个会话、几个进行中。

**它只是一块屏幕**：没有暂停、重跑、改参数——一个操作按钮都没有。看不看它，委托照跑。

---

## 四、代价（开之前想清楚这条）

**开着就等于「本机磁盘上存在全部委托原文」。**

桥平时的诊断日志**刻意不落 prompt 全文**；观测台会落。临时目录只解决「不长期留存」，
**运行期间那里就是一份全量明文，同一台机器上任何进程都读得到**。

页面这一侧：只听 `127.0.0.1`、不出网、页面内容不会发到任何地方——但它是一个**没有鉴权**
的本地端口，同机其它进程能读到这次运行的全部内容。

**结论**：敏感内容的委托，别开。

---

## 五、记录什么时候就没了

- **那次运行正常结束时，整个目录被删掉**——这是有意的，不在你机器上长期留存对话内容。
  所以要看就在运行期间看。
- 客户端被强杀导致目录留下时，`node scripts/agent-bridge.mjs cleanup` 会扫掉那些
  **owner 已经不在**的目录（活着的 run 不会被动到）。
- 页面在运行结束后会如实说「该运行已结束，实时记录已随之清除」，并给出终态画面——
  那是正常收尾，不是错误。

## 六、开了却看不到东西

| 现象 | 多半是 |
|---|---|
| tmpdir 里一个 `agent-bridge-viz-*` 都没有 | 开关没生效：改完没重启客户端，或环境变量没传给 server 进程 |
| 目录在，但 viewer 起不来说「读不到 meta.json」 | 目录传错了（传成了上级目录，或传到了端口位上） |
| 页面显示「该运行已结束」 | 那个 run 的 owner 进程已经没了（客户端退了）——换最新那个目录 |
| 页面显示「未观测到正常收尾」 | 那次运行是被强行终止的，来不及写下结局。工作副本、日志往往都还在 |
