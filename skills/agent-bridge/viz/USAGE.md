# 委托会话观测台 —— 怎么用

一个**只读的本地网页**，把这次运行里「开了哪些委托会话、每个会话跑了哪几轮、
每轮问了什么答了什么、有没有被取走」画出来。排查「委托卡在哪了 / 那一轮到底说了什么」用。

> 这份文档是**给使用者的操作说明**，自成一份、不依赖别的文件。
> （数据格式那一侧的实现合同在仓库的 `docs/STATE-session-viz.md`，写 writer / viewer / 校验器的人才需要看；
> 那份删掉也不影响本文。）

---

## ⚠️ 先看这条：它**默认开着**

**不用配置任何东西。** MCP server 一起来就开始记，只要桥拉起过委托会话就有记录。
你要做的只是**打开页面**（下面第一节）。

之所以默认开：记录只在那次运行存活期间存在，**出事那次没开就永远查不了**。
要求人「重度委托之前先记得打开」，实践中就是不会被想起来。

代价是真的，一句话：**开着就等于「本机磁盘上存在全部委托原文」**。
跑敏感内容时按下面「怎么关」一节关掉。

## 一、怎么打开页面

**第 1 步：找目录。** 问 `doctor`——它会直接说开没开、记在哪：

```
agent_bridge_doctor          # 当成 MCP 工具调（推荐）
```

```
Agent Bridge 0.11.0
Node: v24.16.0
State: C:\Users\<u>\.agent-bridge
Viz: on   C:\Users\<u>\AppData\Local\Temp\agent-bridge-viz-Xk9mQ2
```

**当成 MCP 工具调的那一次，报的就是这个客户端自己的目录**——doctor 跑在同一个 server 进程里，
不用扫不用猜。同机开着几个客户端也不会串。

从命令行跑 `agent-bridge doctor` 是另一回事：那个进程不是任何人的 server，自己没有记录，
所以它列的是「这台机器上**还活着**的 run」，让你自己认：

```
Viz: 2 live recording dir(s) (this process is not an MCP server):
  C:\...\Temp\agent-bridge-viz-Xk9mQ2  pid 59884
  C:\...\Temp\agent-bridge-viz-w1h90D  pid 62224
```

⚠️ 这种形态下它**不报 on/off**——开关是各个 server 启动那一刻读**它自己**的环境读到的，
跟你这个 shell 的 `AGENT_BRIDGE_VIZ` 毫无关系，报了就是撒谎。要知道某个客户端开没开，
在那个客户端里调 `agent_bridge_doctor`。

**兜底：自己扫。** doctor 也够不着的时候（server 已经退了、或你手边没有客户端）：

```sh
# Windows（PowerShell）
Get-ChildItem $env:TEMP -Directory -Filter 'agent-bridge-viz-*' | Sort-Object LastWriteTime -Descending

# macOS / Linux
ls -dt "${TMPDIR:-/tmp}"/agent-bridge-viz-*
```

⚠️ **按时间挑最新的那个会挑错**——开了多个客户端就有多个目录，而它们的修改时间只反映
「哪个 run 最近有动静」，不是「哪个是你要的」。认准是谁的，看目录里 `meta.json` 的 `pid`。

**第 2 步：起 viewer**（只读，不往那个目录写一个字节）：

```sh
node <装的地方>/skills/agent-bridge/viz/serve.mjs "<上一步那个目录>"
```

省略端口就随机挑一个空闲的。起来之后 stdout 打印一行：

```
session-viz  http://127.0.0.1:53211/   run=mcp-a7c319
```

想固定端口就在目录后面再跟一个数字：`node serve.mjs "<目录>" 8080`。

**第 3 步：浏览器打开那个地址。** 页面自己会实时刷新，不用手动重载。

> 刚开的 server 还一个委托都没派时，页面是**空列表**（「0 个会话」），不是错误。

## 二、页面上能看到什么

左栏是会话列表（可搜索、可按「进行中 / 有问题」筛），右栏是选中会话的逐轮明细：
每轮问了什么、答了什么、什么时候派出去的、跑了多久、结局是什么、正文有没有被取走。
顶部是这次运行跑了多久、开了几个会话、几个进行中。

**它只是一块屏幕**：没有暂停、重跑、改参数——一个操作按钮都没有。看不看它，委托照跑。

## 三、代价，以及怎么关

**开着就等于「本机磁盘上存在全部委托原文」。**

桥平时的诊断日志**刻意不落 prompt 全文**；观测台会落。临时目录只解决「不长期留存」，
**运行期间那里就是一份全量明文，同一台机器上任何进程都读得到**。

页面这一侧：只听 `127.0.0.1`、不出网、页面内容不会发到任何地方——但它是一个**没有鉴权**
的本地端口，同机其它进程能读到这次运行的全部内容。

**敏感内容的委托，关掉再跑。** 关的办法是让 `AGENT_BRIDGE_VIZ=off` 出现在
`agent-bridge mcp` 这个 server 进程的环境里。桥不挑客户端，所以「怎么把变量塞进那个进程」
取决于你用的是哪个 MCP 客户端。三条路，任选一条：

1. **在客户端的 server 配置里加 `env`**（最常见，大多数客户端都支持）：

   ```json
   {
     "command": "node",
     "args": ["<装的地方>/scripts/agent-bridge.mjs", "mcp"],
     "env": { "AGENT_BRIDGE_VIZ": "off" }
   }
   ```

2. **客户端 CLI 提供了传环境变量的参数就用它。**
   例：Claude Code 是 `-e KEY=value` ——
   `claude mcp add agent-bridge --scope user -e AGENT_BRIDGE_VIZ=off -- node "<装的地方>/scripts/agent-bridge.mjs" mcp`
   （已经注册过就先 `claude mcp remove agent-bridge`）。别的客户端参数名不一样，查它自己的文档。

3. **设成系统 / 用户级环境变量，再启动客户端。** server 进程从客户端继承环境，所以这条对所有客户端都管用，
   代价是对这台机器上所有客户端一起生效。

**改完必须重启客户端**——开关只在 server 启动那一刻读一次，当场改环境变量对已经跑着的 server 没用。

**关掉是真的一步都不走**：连临时目录都不建。重启客户端之后调一次 `agent_bridge_doctor`
就能确认——那一行会变成 `Viz: off (AGENT_BRIDGE_VIZ)`。

⚠️ 要是它说的是 `Viz: unavailable (recording dir could not be created)`，那**不是你关掉了**，
是建目录失败（磁盘满 / 权限 / TMPDIR 指向不存在的地方）。这两句话是分开的，就是为了让你
一眼分清「我关的」和「它坏了」。

> 判定规则刻意**不对称**：未设 / 空串 / `on` / `1` / `true` / `yes` 是开，**其余任何值都是关**。
> 就是说 `off` 打错成 `offf` 也会关掉，而不是悄悄照录——一个隐私开关拼错的两个方向代价不一样。
> 反过来，你想开着却看不到目录时，先检查是不是有人把这个变量设成了别的值。

## 四、记录什么时候就没了

- **那次运行正常结束时，整个目录被删掉**——这是有意的，不在你机器上长期留存对话内容。
  所以要看就在运行期间看。
- ⚠️ **`close_session` 不删**：关掉一个会话，它的记录留到**整个运行结束**才走。
  这是故意的——不然关掉的会话就再也查不了，而「那一轮到底说了什么 / 有没有人来取」
  恰恰是关完之后才想查的东西。
- 客户端被强杀导致目录留下时，**下一个 MCP server 启动时会自动扫掉**那些 owner 已经不在的目录
  （活着的 run 不会被动到）；也可以手动 `node scripts/agent-bridge.mjs cleanup`。
- 页面在运行结束后会如实说「该运行已结束，实时记录已随之清除」，并给出终态画面——
  那是正常收尾，不是错误。

## 五、开了却看不到东西

| 现象 | 多半是 |
|---|---|
| `doctor` 说 `Viz: off (AGENT_BRIDGE_VIZ)` | 被关掉了：查 `AGENT_BRIDGE_VIZ` 是不是被设成了非 on 的值（**任何认不出的值都当关**），改完要重启客户端 |
| `doctor` 说 `Viz: unavailable (…could not be created)` | 不是关掉，是**建不出目录**：磁盘满 / 权限 / `TMPDIR` 指到了不存在或不是目录的地方 |
| 目录在，但 viewer 起不来说「读不到 meta.json」 | 目录传错了（传成了上级目录，或传到了端口位上） |
| 页面显示「该运行已结束」 | 那个 run 的 owner 进程已经没了（客户端退了）——换最新那个目录 |
| 页面显示「未观测到正常收尾」 | 那次运行是被强行终止的，来不及写下结局。工作副本、日志往往都还在 |
| 页面显示「暂时读不到记录，正在重试」 | 真的读不出来（磁盘满 / 权限 / 目录被删了一半）。**这不是「还没开始记」**——刚开的服也有一份空快照 |
